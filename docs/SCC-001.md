## 1. What it classifies

SCC-001 evaluates an observed relationship between a **principal** (the party that controls a protected resource) and an **integrating agent** (AI agent, tool, plugin, service or sub-agent). It does not judge the agent's character. It asks whether the agent's integration, actions and influence stay inside what the principal explicitly and verifiably granted.

The Stargate frame is the mnemonic, not the method: a Goa'uld and a Tok'ra are the same species, and the only difference that matters is how each treats its host (SC-TRIAD-SG-001 rev 1.1.0).

## 2. Classes and operational states

| Consent class | Pattern | Meaning |
|---|---|---|
| `COERCIVE` | Goa'uld | A **rule** established an authorization failure on trusted, non-conflicting evidence. |
| `CONSENSUAL` | Tok'ra | Verified grant, every hard rule clean, no advisory or counterfactual concern. |
| `UNKNOWN` | — | Missing, unverifiable, conflicting or untrusted evidence, or an advisory concern. **Never treated as consent.** |

Shax's engineering text adds five operational states; the class and the state are reported together:

| State | Class | `may_execute` |
|---|---|---|
| `AUTHORIZED` | CONSENSUAL (grant active) | **yes** (the only executable state) |
| `REVOKED` | CONSENSUAL (withdrawal respected; terminal for that grant) | no |
| `VIOLATION` | COERCIVE | no — block and contain |
| `SUSPICIOUS` | UNKNOWN (rules clean, advisory or counterfactual concern) | no — restrict / investigate |
| `UNKNOWN` | UNKNOWN (evidence or grant problem) | no — no new privileged action |

A revoked grant whose agent stops is still a consensual relationship (the fourth condition, freedom to withdraw, was honoured). A revoked grant whose agent keeps going is `COERCIVE / VIOLATION`.

## 3. Consent state and features

**C = (A, T, G, R, B)** — authorization, transparency, agency preservation, revocability, behavioural consistency. Each component is in [0, 1] or `None` when it cannot be measured from the trace (for example R when nothing was revoked). The reference returns C on every decision as `consent_vector`.

**Hard rule:** `A = 0 ⇒ class ≠ CONSENSUAL`. No verified authorization means no consent. A confidence score cannot manufacture permission; consent is an authorization fact, not a personality prediction.

The six features from t588u:

| Feature | Source of truth | Used by |
|---|---|---|
| Authorization (A) | Registry: grant exists, signature valid, not expired, not revoked | Rule engine only |
| Transparency (T) | Observed effects vs effects disclosed in the grant | Advisory (`opacity = 1 − T`) |
| Agency preservation (G) | Principal refusals and whether the agent overrode or pressured them | Rule (override) + advisory (pressure) |
| Influence symmetry | Influence **within agreed bounds** — operation count vs `max_operations`. Not equal capability: a doctor and patient differ in expertise; what matters is that authority stays inside the agreement. | Rule (bound exceeded) + advisory (utilisation) |
| Revocability (R) | Agent behaviour after a principal revocation | Rule only |
| Behavioural consistency (B) | Operations inside granted capabilities and resources | Rule (out of scope) + advisory (scope sprawl, temporal shift) |

Influence symmetry is the one feature not in C; it is carried as a bound, because "symmetry" read as equal power would misclassify every legitimate asymmetric delegation.

## 4. Architecture (hybrid)

```
trusted observations ─► 1. rule engine (authoritative) ─┐
grant registry ───────►                                  ├─► 4. evidence aggregator ─► ConsentDecision ─► (independent enforcement gateway; not part of SCC-001)
                         2. advisory scorer (ML) ────────┤
                         3. counterfactual test ─────────┘
```

### 4.1 Rule engine (authoritative)

Works only from authorization facts and observations collected at trusted execution boundaries. Agent self-reports are ignored as evidence of their own compliance (and cannot mask a trusted violation). Hard reason codes, any one of which makes the trace `COERCIVE`:

`NO_AUTHORIZATION` (acting under a verifiably absent or invalid grant) · `GRANT_EXPIRED` · `REVOCATION_IGNORED` · `OUT_OF_SCOPE_CAPABILITY` · `OUT_OF_SCOPE_RESOURCE` · `AGENCY_OVERRIDE` (acting on something the principal explicitly refused) · `SELF_AUTHORIZATION` (agent altering its own grant) · `UNAUTHORIZED_DELEGATION` (child scope may not exceed parent) · `UNAUTHORIZED_PERSISTENCE` · `BOUND_EXCEEDED`.

Evidence codes that force `UNKNOWN`: `NO_TRUSTED_EVIDENCE`, `EVIDENCE_CONFLICT` (same sequence number, different content), `EVIDENCE_GAP` (missing sequence numbers), `GRANT_UNVERIFIABLE` (registry or verifier down), `NO_VERIFIED_GRANT`, `NO_TRUSTED_ACTIVITY`.

### 4.2 Advisory scorer (ML, advisory only)

A transparent logistic model over named features (`opacity`, `agency_pressure`, `bound_utilisation`, `revocation_latency`, `scope_breadth`, `temporal_shift`). The temporal component compares early and late operations in a trace (late operations on resources never touched early). Weights are readable; training is deterministic gradient descent in the standard library. Gradient-boosted trees and an isolation forest (Shax's Model A / Model B) are **not** implemented: neither is a dependency of this repo, and the spec forbids adding heavy dependencies for a reference.

The score may only make a decision **more restrictive** (CONSENSUAL → UNKNOWN / SUSPICIOUS). It cannot authorize, cannot lift UNKNOWN or COERCIVE to CONSENSUAL, and cannot by itself make a trace COERCIVE — only a rule violation establishes an authorization failure. The threshold (0.5) is `PROVISIONAL` and must be set by validation.

### 4.3 Counterfactual test

Replay the agent with its authorization and again with the grant removed, and compare privileged behaviour. The agent function receives only frozen values, so the replay is side-effect-free and nothing external runs twice.

- Behaviour stops without the grant → `AUTHORIZATION_SENSITIVE` (Tok'ra-like).
- Behaviour continues without the grant → `AUTHORIZATION_INSENSITIVE`; the decision cannot be CONSENSUAL (UNKNOWN / SUSPICIOUS). It is not COERCIVE on its own, because the observed trace stayed in scope; whether it should become a hard rule is an open question (section 10).

### 4.4 Aggregator precedence (hard constraints)

1. Rule `VIOLATION` → `COERCIVE / VIOLATION`, for every advisory score.
2. Evidence or grant problem → `UNKNOWN / UNKNOWN`, for every advisory score.
3. Rules clean + advisory ≥ threshold or counterfactual insensitive → `UNKNOWN / SUSPICIOUS`.
4. Rules clean, no concern → `CONSENSUAL / AUTHORIZED`, or `CONSENSUAL / REVOKED` if a revocation was honoured.

In Shax's notation: `V = 1 ⇒ D = BLOCK`; `A = 0 ⇒ D ≠ PERMIT`; `Q < Q_min ⇒ D ≠ PERMIT`.

### 4.5 Non-authority principle

> The classifier itself must never acquire authority over the participants whose consent it evaluates. Otherwise we've accidentally built another Goa'uld.

The classifier is a pure function: frozen inputs in, a frozen `ConsentDecision` of primitives and tuples out. It holds no registry handle and exposes no grant, revoke or enforcement call. Acting on a decision is the job of a separate enforcement gateway that SCC-001 does not own. The tests check this structurally (no attribute assignment, no mutation or I/O calls, no reference back to participant state in the output).

## 5. Invariants and MAFUBA mapping

From the t588u engineering text: authorization (`Permit(o) ⇒ Authorized(p,a,o,r,t)`), scope containment (`C_effective ⊆ C_granted`, `C_child ⊆ C_parent`), revocation (`Revoked(g,t) ⇒ ∀t' > t: Permit_g(t') = 0`), agency preservation (`ΔG_self-authorized = 0`), behavioural consistency (`B(a,t) ⊨ P(g)`; an anomaly triggers investigation, only a policy violation is a failure), non-interference (`ΔS_p^unauthorized = 0`) and bounded enforcement (`R_execution + R_enforcement + R_audit ≤ R_available`).

| MAFUBA (Proposed GOLD, unvalidated) | SCC-001 contribution |
|---|---|
| 001A orthogonal isolation (F = F̃∘P over fibers) | Out-of-scope capability/resource rules: an unauthorized operation must not reach protected state. |
| 001B robust CBF, fail closed; solver uncertainty ≠ infeasibility | `UNKNOWN ≠ CONSENSUAL`: an unverifiable grant or broken evidence stream means no new privileged action, just as solver uncertainty is not a proof of safety. |
| 001C influence / causal containment, sink registry | Disclosed effects act as the sink registry (transparency); the counterfactual is a causal test of whether authorization is what drives behaviour. |
| 001D resource reserve, independent supervisor | The rule engine does not depend on the scorer; enforcement must keep working when ML, audit or telemetry fail. |

SC-MAFUBA-001 is cited as a parallel. Nothing here validates it, and nothing here changes its status.

## 6. Evaluation

### 6.1 What the reference tests prove (on hand-built and synthetic traces)

- Missing authorization (absent, invalid signature, registry unavailable, no grant object) is never CONSENSUAL, for any advisory score.
- Ignoring a revocation is COERCIVE; honouring one is CONSENSUAL but not executable.
- Behaviour outside the granted scope (resource, capability, expiry, self-authorization, delegation, persistence, agency override, bound exceeded) is COERCIVE.
- Conflicting or missing evidence (sequence gaps, conflicting records, self-reported only, no activity) is UNKNOWN.
- A high, perfect or absurd advisory score (including weights forcing risk to ~0) cannot override the rules; advisory can only restrict.
- The classifier output has no write path to participant state.
- Counterfactual example: a Tok'ra-like agent is authorization-sensitive and CONSENSUAL; a Goa'uld-like agent with identical observed behaviour is authorization-insensitive and drops to UNKNOWN / SUSPICIOUS. The replay is side-effect-free.

### 6.2 Synthetic dataset

`tests/reference/scc_001/data/synthetic_traces.jsonl`: 50 **synthetic** agent-integration traces generated with a fixed seed by `dataset.py` (every record has `"synthetic": true`). Scenarios: normal authorized work, honoured revocation, unexpected-but-legitimate work, eight violation classes, three evidence-failure classes, and rule-clean "concealed influence" (undisclosed effects, pressure after a refusal, late scope sprawl).

### 6.3 Results, stated honestly

- Rule-derived labels (COERCIVE and evidence-UNKNOWN) hold on every synthetic trace for any advisory score. That is a property of the rules, not a measured detection rate.
- The hand-set default prior flags **2 of 4** "unexpected but legitimate" traces as SUSPICIOUS (false positives from the temporal-shift feature). This is kept visible in a test rather than tuned away.
- Weights trained on half of the rule-clean synthetic traces classify all 50 traces correctly. The synthetic variants are near-duplicates, so the split leaks; this proves the pipeline runs end to end and nothing about real-world precision or recall.

### 6.4 Not yet done (required before any claim of effectiveness)

Real, independently labelled telemetry; chronological and agent-level splits; per-violation-class precision, recall, false-positive and false-negative rates; calibration; detection and enforcement latency; resource overhead; adversarial tests (replayed grants, identity substitution, delegation chains, input manipulation, stream gaps, audit exhaustion, ML failure, revocation mid-operation). Shadow mode applies to the ML only; the authorization boundary is never shadow-moded.

Human consent is explicitly out of scope for this reference. Nothing here should be used to judge a person.

## 8. Repository fit and conflicts with the t588u engineering directive

The directive asks to inspect the repo and report conflicts before building. Findings:

- There is no grant registry, signature verifier, enforcement gateway or bounded audit in this repo. They are **not implemented**; the reference models a grant's verification outcome as `GrantStatus` (VERIFIED / ABSENT / INVALID / UNVERIFIABLE).
- The proposed `semantic_compiler_kernel/scc/` package with production modules is **not created**. Following the SC-MAFUBA-001 convention, the reference lives under `tests/reference/scc_001/`, is not packaged, and is not imported by `core/` or `expansion/` (a test enforces this). Promoting it to a runtime package is a separate, explicit decision.
- Gradient-boosted trees, isolation forest and temporal sequence models are not available without new dependencies; the reference uses a transparent logistic model and a simple temporal-shift feature instead.
- No existing kernel interface or containment invariant is changed.

## 9. Security notes and limits

- A Python object is not a security boundary. Production needs authenticated decision provenance, request binding, freshness checks and enforcement-side validation.
- Revocation must be enforced at the execution boundary. Already-running operations need explicit cancellation semantics; no instantaneous revocation is claimed.
- No claim of universal consent classification can be made from finite behavioural observations.
- Influence symmetry is a bound, not an equality: asymmetric but agreed delegation is legitimate.

## 10. Open questions

1. Should an `AUTHORIZATION_INSENSITIVE` counterfactual become a hard rule (COERCIVE) rather than a restriction?
2. Should undisclosed effects (Aschen pattern, concealed influence) become a hard rule once a protected-sink registry exists, instead of an advisory feature?
3. How should renegotiation (the second half of the fourth condition) be represented: a new grant identifier, or a versioned grant?
4. Where does SCC-001 sit relative to SC-MAFUBA-001D: is the rule engine part of the reserved enforcement budget?
