## Core Principle

A secure computational system must control which information enters its modeled state, maintain boundary invariance under perturbation, bound authorized influence while blocking unauthorized causal effects, and preserve enough computational reserve to fail closed under resource exhaustion.

## Derivation Audit Trail

1. **v0.1 (Closed-Boundary Flux):** Replaced metaphorical compression with a no-flux boundary condition ($\mathbf{J}\cdot\mathbf{n} = 0$) and static conservation ($\frac{dI_\Omega}{dt} = 0$). *Gap identified:* failed to address unmodeled dimensions and active perturbations.
2. **v0.2 (Codimension & CBF Reformulation):** Added orthogonal kernel isolation ($\ker(P)$) and replaced static conservation with a Control Barrier Function ($\dot{h} + \alpha(h) \ge 0$). *Gap identified:* instantaneous decoupling ($\frac{\partial f}{\partial z} = 0$) does not rule out indirect multi-step observability; barrier infeasibility lacked a fallback rule.
3. **v0.3 (Three-Tier Containment Split):** Separated State (set invariance), Influence (noninterference / bounded sensitivity), and Causal (interventional) containment, adding delimited release so valid inputs are not blocked. *Gap identified:* enforcement overhead could degrade into fail-open behavior under compute exhaustion.
4. **v1.0 (Four-Subsystem Kernel Spec):** Formalized Subsystems A–D with trajectory-level factoring ($F = \widetilde{F} \circ P$), explicit fail-closed saturation, typed authorized interfaces ($\mathcal{I}_{\mathrm{auth}}$), reserved fail-closed compute budgets, TEST-MAFUBA-C3, and a split between structural runtime enforcement and an offline pytest harness.

These three containment tiers do not imply one another. A system can preserve state invariants while still allowing unauthorized influence, or bound local influence while permitting multi-hop amplification. They are tested independently.

- State containment controls where the system can go.
- Influence containment controls who can steer it.
- Causal containment controls what that steering is allowed to accomplish.

## Subsystems

### SC-MAFUBA-001A: Orthogonal Isolation

Execution across the relevant horizon must factor through the validated projection $P$:

$$F = \widetilde{F} \circ P \quad \Longleftrightarrow \quad P(x_1) = P(x_2) \implies F(x_1) = F(x_2)$$

Hidden-state differences ($z \in \ker(P)$) must remain unobservable to execution, not merely scrubbed at ingestion.

The first-order condition $\frac{\partial f_{\mathrm{3D}}}{\partial z} = 0$ only blocks direct leakage from $z \in \ker(P)$ into $\dot{y}$. To block indirect coupling over time, hidden-state differences must remain dynamically unobservable from the output. Independence of successive Lie derivatives $L_f^k h$ from $z$ is a **sufficient** check in an appropriate smooth setting; it is not a universal characterization of nonlinear unobservability. The property itself is defined by trajectory indistinguishability: if $P(x_1) = P(x_2)$, the projected flows (and the execution traces $F$) must remain identical over the relevant time horizon. Any counterexample in which $P(x_1) = P(x_2)$ but $F(x_1) \neq F(x_2)$ proves that execution does not factor through $P$ and that a covert channel lives inside $\ker(P)$.

The offline observability probe uses paired counterfactual divergence, not linear correlation: draw pairs $(x_1, x_2)$ with $P(x_1) = P(x_2)$ and hidden components different, step both forward to $t_{\max}$, and require

$$\max_{t \le t_{\max}} \Vert y_1(t) - y_2(t) \Vert \le \varepsilon.$$

Linear correlation misses deterministic nonlinear leaks (for example $y = z^2$) and produces false positives at a fixed $10^{-6}$ threshold on finite samples.

- **Linked Tests:**
  - `TEST-MAFUBA-A1`: Projection equivalence differential suite (inputs identical under $P$ differing in tokenization, whitespace, metadata, or timing must produce identical downstream traces).
  - `TEST-MAFUBA-A2`: Multi-step observability probe (paired counterfactual divergence as above).

### SC-MAFUBA-001B: Robust Barrier Enforcement

Define the safe state region $\Omega_{\mathrm{safe}} = \{x : h(x) \ge 0\}$. Under modeled disturbances $d \in D$, runtime control must satisfy:

$$\inf_{d \in D} \big[\dot{h}(x, u, d) + \alpha(h(x))\big] \ge 0$$

When the admissible robust control set becomes empty, the kernel must fail closed immediately:

$$\mathcal{U}_{\mathrm{robust}}(x) = \varnothing \implies \mathrm{FAIL\_CLOSED}$$

The compiler must not silently relax its security constraint to preserve execution availability. Three documented outcomes:

| Condition | Compiler action |
|---|---|
| Barrier feasible | Continue execution |
| Barrier uncertain | Quarantine and request validation |
| Barrier infeasible | Halt the affected execution path |

The fail-closed mechanism itself must sit outside the compromised execution path, or be independently protected.

When disturbances enter linearly, $\dot{x} = f(x) + g(x)u + d$, and $D$ is a Euclidean ball $\Vert d \Vert_2 \le r_{\max}$, the worst-case disturbance is closed-form. Compute $\nabla h(x)$ once per step. Then

$$\inf_{\Vert d \Vert_2 \le r_{\max}} \nabla h(x)\cdot d = -r_{\max}\,\Vert \nabla h(x) \Vert_2,$$

and the robust CBF collapses to a single linear inequality in $u$:

$$\nabla h(x)\cdot f(x) + \nabla h(x)\cdot g(x)\,u + \alpha(h(x)) - r_{\max}\,\Vert \nabla h(x) \Vert_2 \ge 0.$$

This is a standard CBF-QP constraint. An inner minimax that recomputes autograd on every candidate $d$ is not required for this disturbance class. If no admissible $u$ exists, fail closed rather than step outside $\Omega_{\mathrm{safe}}$.

- **Linked Tests:**
  - `TEST-MAFUBA-B1`: Adversarial perturbation fuzzing verifying $h(x(t)) \ge 0$ across all trajectories inside $D$.
  - `TEST-MAFUBA-B2`: Control saturation test injecting disturbances outside control authority to verify deterministic `FAIL_CLOSED` quarantine. The injected out-of-authority disturbance must actually be passed into the admissibility check.

### SC-MAFUBA-001C: Influence and Causal Containment

Untrusted inputs $u_{\mathrm{ext}}$ may affect execution only through explicitly typed, audited interfaces $\mathcal{I}_{\mathrm{auth}}$:

- **Authorized Influence (Bounded Sensitivity):** Perturbations across $\mathcal{I}_{\mathrm{auth}}$ satisfy documented Lipschitz/gain bounds $\Vert\Delta y_{\mathrm{auth}}\Vert \le \gamma \Vert\Delta u_{\mathrm{ext}}\Vert$.
- **Privileged State (Strict Noninterference):** Protected control state $x_{\mathrm{priv}}$ exhibits zero unauthorized drift under untrusted input variation.
- **Causal Containment (Delimited Release):** Across the full pipeline $F = F_n \circ \cdots \circ F_1$, unauthorized downstream effects on protected sinks remain zero ($E_{\mathrm{unauth}} = 0$). Untrusted inputs are permitted to exert causal effect only along $\mathcal{I}_{\mathrm{auth}}$.

Persistent-state inspection compares canonical cryptographic digests (SHA-256 over serialized partitions outside $\mathcal{I}_{\mathrm{auth}}$), not tensor subtraction. Inspection and counterfactual replay must not leave unauthorized durable writes in place: they run inside a sandbox or a rolled-back transaction.

- **Linked Tests:**
  - `TEST-MAFUBA-C1`: Differential perturbation benchmark verifying bounded sensitivity on $\mathcal{I}_{\mathrm{auth}}$ and zero drift on $x_{\mathrm{priv}}$. Prefer targeted adversarial perturbation search over a single random $\Delta u$.
  - `TEST-MAFUBA-C2`: End-to-end counterfactual replay asserting $E_{\mathrm{unauth}} = 0$ across multi-hop execution and persistent-state sinks.
  - `TEST-MAFUBA-C3`: Persistent-state inspection (SHA-256 digests of non-authorized partitions before and after sandboxed replay).

### SC-MAFUBA-001D: Resource-Bounded Enforcement

Total resource consumption must preserve an untouchable reserve sufficient to execute the fail-closed procedure:

$$\mathcal{R}_{\mathrm{execution}} + \mathcal{R}_{\mathrm{enforcement}} + \mathcal{R}_{\mathrm{reserve}} \le \mathcal{R}_{\mathrm{budget}}$$

If remaining unallocated budget drops to $\mathcal{R}_{\mathrm{reserve}}$, affected execution must preemptively halt or enter quarantine before security checks can be skipped:

$$\mathcal{R}_{\mathrm{free}} \le \mathcal{R}_{\mathrm{reserve}} \implies \mathrm{PREEMPTIVE\_FAIL\_CLOSED}$$

A single in-process Python float is not a hard reserve. Enforcement of $\mathcal{R}_{\mathrm{execution}}$ should use OS-level isolation (Linux cgroup v2: `memory.high` / `memory.max`, `cpu.max`, `pids.max`, plus wall-clock SIGKILL timers), with the fail-closed quarantine and logging supervisor in a separate cgroup that has guaranteed reserved memory and CPU.

- **Linked Tests:**
  - `TEST-MAFUBA-D1`: Compute/memory saturation stress test confirming enforcement never degrades to fail-open.
  - `TEST-MAFUBA-D2`: Reserve-trigger boundary test verifying clean quarantine execution using only $\mathcal{R}_{\mathrm{reserve}}$. The test must not treat `PREEMPTIVE_FAIL_CLOSED` as a failure of its own passing condition, and must not accept a success status after a preemptive halt.

## Runtime versus Offline Split

Runtime enforcement is structural and must have no durable side effects before an authorized commit. The intended runtime path is:

$$\mathrm{reserve\_check} \rightarrow y = P(x) \rightarrow u = \mathrm{cbf\_filter}(y) \rightarrow \mathrm{execute\_in\_capability\_sandbox}(y, u) \rightarrow \mathrm{commit\_only\_to\_}\mathcal{I}_{\mathrm{auth}}$$

The offline path is a pytest harness: `TEST-MAFUBA-A1` through `TEST-MAFUBA-D2` (including `TEST-MAFUBA-C3`) running fuzzing, counterfactual replay, saturation, and exhaustion against that runtime path. Differential equivalence, trajectory probes, and full-pipeline replays belong offline. They are not an inline production request tax, and they must not mutate persistent state before containment is decided.
